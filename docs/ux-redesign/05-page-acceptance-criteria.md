## A. เกณฑ์ร่วม (ทุกหน้า)

**A1 Usability — ตอบ YES ได้ทั้ง 7 ข้อ ด้วยหลักฐานจากการทดสอบกับผู้ใช้จริง (ไม่สอน ไม่ชี้ปุ่ม)**

| # | คำถาม | ผล |
|---|---|---|
| 1 | ผู้ใช้ใหม่เข้าใจวัตถุประสงค์ของหน้าเอง | NOT RUN |
| 2 | ระบุได้ว่าต้องเริ่มตรงไหน | NOT RUN |
| 3 | รู้ว่าปุ่มใดเป็นการกระทำหลัก | NOT RUN |
| 4 | ทำ Workflow หลักสำเร็จโดยไม่มีคนสอน | NOT RUN |
| 5 | เข้าใจผลลัพธ์หลังดำเนินการ | NOT RUN |
| 6 | เมื่อทำผิด รู้วิธีแก้ | NOT RUN |
| 7 | ไม่ต้องใช้คู่มือหรือคำอธิบายเพิ่ม | NOT RUN |

**A2 รักษาของเดิม (P0-A):** Preserve List (`02` §1) ทุกข้อที่เกี่ยวกับหน้านั้นยังอยู่และทำงานเท่าเดิม
**A3 ตัวอักษร:** ไม่เล็กกว่าเดิมสำหรับ Element เดียวกัน (วัดก่อน/หลัง) · ข้อความหลัก ≥ ขนาดเดิม
**A4 Contrast:** ข้อความปกติ ≥ 4.5:1, องค์ประกอบ UI ≥ 3:1 ทุกสถานะ (Default, Hover, Active, Focus, Disabled, Error, Selected) ทั้ง Light/Dark และบนพื้น Navy พร้อมวิธีวัด
**A5 Keyboard:** Tab ไปถึงทุกการกระทำตามลำดับอ่าน, Focus เห็นชัด (บน Navy: ขาวหรือ `#5FE3A8`), Esc ปิด Dialog/Panel และคืน Focus
**A6 Status:** สี + ข้อความ + ไอคอน (ไม่พึ่งสีอย่างเดียว) ใช้ Label เดิม ไม่เพิ่มสถานะ
**A7 Responsive:** ทดสอบที่ 1440, 1024, 768, 390px และ Zoom 200% ไม่มีเนื้อหาถูกตัด (ยังไม่ได้ทดสอบ)
**A8 States:** มี Loading (Skeleton), Empty (บอกขั้นต่อไป), Error (สาเหตุ + วิธีแก้), Success (หลัง Server ยืนยัน), Disabled (บอกเหตุผล)
**A9 สิทธิ์:** ผู้ใช้เห็นเฉพาะที่ Role มีสิทธิ์ และ Server ตรวจทุก API (ไม่พึ่งการซ่อน UI) การเข้าหน้าตาม `ROUTE_ACCESS` [V-src `client/src/lib/routeAccess.ts`] ต้องไม่เปลี่ยน:

| Route | ผู้เข้าได้ |
|---|---|
| `/settings` | `isSuperAdmin` เท่านั้น |
| `/giving-guide` | `canCountOfferings` หรือ `canViewFinanceRecords` |
| `/counting` (+`/:id`) | `canCountOfferings` |
| `/transactions`, `/offerings` | `canViewFinanceRecords` |
| `/offerings/new`, `/giving/inbox` | `canManageFinance` |
| `/expenses`, `/funds` | `canManageFinance` หรือ `canManageChurchSettings` |
| `/budgets` | `canManageBudgets` |
| `/reports` | `canViewReports` |
| `/approvals` | `canManageFinance` หรือ `canManageChurchSettings` หรือผู้ลงนามธนาคาร (`isBankSigner`) |
| `/members` | SUPER_ADMIN, PASTOR, TREASURER, DEACON |
| เส้นทางที่ไม่มีใน map (เช่น `/`, `/profile`, `/notifications`, `/ministries`, `/updates`, `/ui-showcase`) | ผู้ล็อกอินทุกคน |
| สมาชิกทั่วไป (station-only) | เข้าได้เฉพาะ `/giving/station`, `/give`, `/privacy`, `/404`, `/withdrawals/new` ที่เหลือถูกส่งไป `/giving/station` |
**A10 ภาษา:** ใช้ Glossary (`06`) ไม่มีรหัสภาษาอังกฤษที่ผู้ใช้ไม่จำเป็นต้องรู้
**A11 ข้อมูล:** ไม่ใช้ข้อมูลตัวอย่างใน Artifact เป็นข้อมูลจริง; ทดสอบบน DB ที่ไม่ใช่ Production
**A12 Offline / Network (TBD-6):** เมื่อ Offline ปุ่มและฟอร์มที่เขียนข้อมูลการเงินต้องใช้ไม่ได้และบอกเหตุผลด้วยข้อความเข้าใจง่าย (ข้อมูลที่กรอกยังอยู่); **ห้าม Queue ธุรกรรมส่งอัตโนมัติเมื่อกลับ Online** (ต้องทดสอบจริงว่า Mutation ไม่ถูก pause แล้วส่งต่อ — ค่าเริ่มต้นของ TanStack Query 5.90.2 ทำเช่นนั้น [V-src]); กด Submit ซ้ำไม่ทำให้เกิดรายการซ้ำ; สถานะ **NOT VERIFIED** จนกว่าทดสอบ
**A13 Motion (TBD-2):** Animation เฉพาะที่สื่อสารสถานะ; ทุกตัวปิดได้ด้วย `prefers-reduced-motion`; ตัวเลขทางการเงินไม่มี Animation (ไม่นับขึ้น/เลื่อน/จาง); ไม่ใช้ Motion Library ใน Phase 1
**A14 Radius (TBD-15):** ค่าเริ่มต้น 14px; Card ที่เหมาะสม 20px; กำหนดตามประเภท Component ไม่ใช้ค่าเดียวทุกองค์ประกอบ; ต้องมีตารางรายชื่อ Component ต่อค่า
**A15 Typography (TBD-16):** ภาษาอังกฤษใช้ Manrope, ภาษาไทยใช้ IBM Plex Sans Thai, ไม่มี Plus Jakarta Sans เป็น Display; โหลดเฉพาะน้ำหนักที่ใช้จริง (วัดจำนวนไฟล์/ขนาดก่อน-หลัง); ขนาดตัวอักษรไม่เล็กกว่าเดิม (TBD-22)
**A16 Emerald บนพื้นมืด:** ข้อความปกติบนพื้นมืดใช้ `#3dd68c`/`#5FE3A8` ไม่ใช้ `#087f5b` (3.54/3.85 [V] คำนวณ)

## B. เกณฑ์เฉพาะหน้า (อัปเดตจากการอ่านซอร์สทุกหน้า)

ป้าย: [V-live] เว็บจริง · [V-src] ซอร์ส · [NV] ยังไม่ได้ตรวจ ทุกหน้ายังต้องผ่าน A1–A16

### B1 `/login`
- Preserve [V-live]: แยกสองฝั่ง, ปุ่ม "เข้าสู่ระบบด้วย LINE", ข้อความอธิบายสิทธิ์, ลิงก์ PDPA, หัวข้อ 1 บรรทัดที่ 390/768/1440
- Preserve [V-src `Login.tsx`]: สถานะหลังล็อกอิน 2 แบบ — `pending` "รอการมอบหมายสิทธิ์ใช้งาน" (อธิบายว่าผู้ดูแลอนุมัติได้จากหน้าการตั้งค่า) และ `disabled` "บัญชีนี้ถูกปิดการใช้งาน"; ปุ่มตรวจสถานะปิดขณะ `isFetching` ("กำลังตรวจสอบ...") พร้อม toast "กำลังตรวจสอบสถานะการอนุมัติ..." / "อนุมัติเรียบร้อยแล้ว กำลังเข้าสู่ระบบ"; ข้อผิดพลาด "เข้าสู่ระบบด้วย LINE ไม่สำเร็จ กรุณาลองใหม่"
- Change: Token เท่านั้น ห้ามเปลี่ยน Flow การเข้าสู่ระบบ
- NV: ผลเรนเดอร์ของสถานะ pending/disabled (ต้องล็อกอิน)

### B2 `/` Dashboard
- Preserve: `HeroSection`, `TaskQueue`, `BalanceCard`, `PrimaryActions`, `SecondaryMenu`, `FinancialSummaryRow`, `RecentTransactions`, `BudgetSection`, `ChurchNewsSheet`, การกรอง Role (`canSeeFinance`, `canViewBudgets`), ซ่อน/แสดงยอด
- Change [P]: หัวข้อ/ประโยคเริ่มต้นจากจำนวนงานจริง; Token; ไอคอนสถานะ; Badge เมนูเฉพาะที่มี Endpoint
- Acceptance: (1) Element ใน Preserve ครบทุก Role (2) ประโยคเริ่มต้นตรงกับจำนวนใน `TaskQueue` ทุกกรณีรวม 0 งาน (3) ตัวเลขการเงินตรงเดิม (4) ไม่มีกราฟรายสัปดาห์ถ้าไม่มี Endpoint
- **ข้อบกพร่องเดิมที่ต้องยืนยัน:** ปุ่ม "ถวายทรัพย์ (Giving Station)" เรียก `/giving-station` แต่ Route คือ `/giving/station` [V-src `Home.tsx:299`, `App.tsx:284`]

### B3 `/transactions`

- Preserve [V-src]: ค้นหา (debounce 300ms), กรองช่วงเวลา/กองทุน/ประเภท, การ์ดสรุป, Export CSV, ปุ่มบันทึกรายจ่าย/การถวาย, cursor pagination, ตาราง 6 คอลัมน์ + `<caption>` + `scope`, ฟีดมือถือจัดกลุ่มตามวัน, ลิงก์ไป Detail

- Change [P]: Token, ไอคอนสถานะ, Side Panel เป็นตัวเลือก; ห้ามตัดคอลัมน์/ตัวกรอง, ห้ามเพิ่มแถว/ปุ่มรอบนับ, ห้ามเพิ่มสถานะใหม่

### B5 `/counting`, `/counting/:id`
- Access: `canCountOfferings`
- Preserve [V-src]: รายการรอบ แท็บ "ค้างอยู่หรือกำลังนับ"/รอบที่ปิดแล้ว, ค้นหา, เปิดรอบ ("กำลังเปิดรอบ…"), ล้าง/ลบรอบด้วยกล่องยืนยัน; รายละเอียด 5 ขั้น/แท็บ: ซองถวาย → นับเงินสด → เงินโอน / นำฝาก → หักเบิก → สรุป & ปิดรอบ; แก้ไขได้เฉพาะสถานะ `counting`; ปุ่มแก้ไขเพิ่มเติมเฉพาะ `canManageFinance && isUnposted`; Toast: "ส่งนับให้ตรวจสอบแล้ว", "ส่งกลับไปนับใหม่แล้ว", "ตรวจสอบรอบเรียบร้อยแล้ว", "ลงบัญชีเรียบร้อยแล้ว", "ปิดรอบเรียบร้อยแล้ว"
- States: Loading Skeleton; Error "โหลดรอบนับเงินถวายไม่สำเร็จ"; Empty "ยังไม่มีรอบนับเงินถวาย"/"ไม่พบรายการในหมวดหมู่นี้"/"ไม่พบผลการค้นหา…"; รหัสไม่ถูกต้อง "รหัสรอบไม่ถูกต้อง", ไม่พบ "ไม่พบรอบนี้"
- Change [P]: Token และไอคอนสถานะ; ผลกระทบก่อนล้าง/ลบแสดงในกล่องยืนยัน (มีข้อความ "ต้องการล้างรายการซองถวายและผลนับทั้งหมดของรอบ…" อยู่แล้ว)
- Acceptance: ไม่เปลี่ยนสถานะ/สิทธิ์; ถ้า PR #157 Merge ผู้นับล้าง/ลบรอบ `verified` ไม่ได้ และ UI ต้องซ่อน/อธิบาย

### B6 บันทึกถวาย/รายจ่ายและสมุดบัญชี
